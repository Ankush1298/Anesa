# Blueprint v3.1 — Final Database Blueprint

Column-level specifications live in `02-database-history-identity.md` Part 4 (edited in place for v3.1). This document is the authoritative **platform-level** database design: engine, roles, security objects, conventions, migration policy, M1 table set (including tables added since `02`), and the verification harness. Where `02` and this file disagree, this file wins.

---

## 1. Engine and extensions

| Item | Decision |
|---|---|
| Engine | PostgreSQL 15+ (16 preferred). One database per environment; one schema `app` for tenant data; schema `platform` for operator data; (future) `biometrics`, `capture_qr` for optional modules |
| Extensions | `pgcrypto`, `citext`, `pg_trgm`, `btree_gist` (exclusion constraints), `pg_stat_statements`; `vector` only when the AI/RAG milestone starts |
| IDs | UUIDv7 generated in application code (`uuidv7()` helper in one package). DB default is *absent* so tests catch missing IDs |
| Time | `timestamptz` (UTC); campus-local dates stored as `date`; `campuses.timezone` is authoritative |
| Text | UTF-8; `citext` for email; collation default; no locale-specific uniqueness |
| Enums | `varchar` + `CHECK` (list kept in code constants and verified by a test that CHECKs match code) |
| Money | Not in M1. Minor-unit bigint + currency |
| Pool | App connects through PgBouncer (transaction mode) in cloud; `SET LOCAL`-only session state, so safe |

## 2. Database roles and grants

| Role | Purpose | Key grants |
|---|---|---|
| `app_migrator` | Owns all objects; runs migrations in CI/CD | DDL; **never** used by the running app |
| `app_runtime` | API + workers | `CONNECT`; `USAGE` on `app`; `SELECT/INSERT/UPDATE/DELETE` on tenant tables **except** append-only tables (`SELECT, INSERT` only): `audit_events`, `attendance_record_revisions`, `mark_revisions`, `request_approvals`, `request_events`, `ticket_messages`, `outbox_events` (UPDATE only on `processed_at/attempts/last_error` columns via column grant). `NOSUPERUSER NOBYPASSRLS` |
| `app_system` | Schedulers/relays | `EXECUTE` on `SECURITY DEFINER` work-list functions only |
| `platform_ops` | Tenant provisioning CLI | Insert into `platform.*` and `organizations`; seeds tenants by setting tenant context; no BYPASSRLS |
| `app_reporting` (later) | Read replica | `SELECT` only; RLS applies |
| `backup_reader` | Backups | Managed by hosting provider / `pg_dump` role with BYPASSRLS **only for backups**, credential held outside the app |

Default privileges are revoked from `PUBLIC`. Functions used by policies (`app_tenant_id()`, `app_actor_kind()`, `app_student_id()`) are `STABLE`, `SECURITY INVOKER`, owned by `app_migrator`, executable by `app_runtime`.

## 3. RLS objects

Per tenant table (generated by one migration helper, verified by the schema linter):

1. `ENABLE` + `FORCE ROW LEVEL SECURITY`.
2. `tenant_isolation` policy (`USING` and `WITH CHECK` on `organization_id = app_tenant_id()`).
3. Student-bearing tables additionally `student_self_only` RESTRICTIVE SELECT policy (`app_actor_kind() <> 'STUDENT' OR student_id = app_student_id()`), applied to: `attendance_records`, `attendance_summaries`, `course_registrations`, `term_enrollments`, `student_programs`, `section_memberships`, `consents` (subject), `student_guardians`, and (later) `marks`, `results`, `result_lines`, `exam_registrations`, `service_requests` (subject_student_id), `invoices`, `payments`. In M1: `students` (keyed by `id`), `student_programs`, `student_guardians`, `consents`.
4. Indexes lead with `organization_id` for list paths.

Append-only tables carry a `BEFORE UPDATE OR DELETE` trigger raising an exception (defense beyond grants).

## 4. Conventions (final)

All items in `02` §4.1 stand. Additions in v3.1:

| Rule | Detail |
|---|---|
| Optimistic concurrency | Every mutable aggregate has `version int not null default 1`, incremented in the same `UPDATE`. API returns `ETag: "<version>"`; mutations require `If-Match`. Mismatch → 409. Tables in M1: users, students, employees, role_assignments, campuses, departments, programs, cohorts, organization_settings, guardians |
| Immutable columns | Trigger-protected: `students.admission_number` (after set; correction via audited SQL function), `*.organization_id`, `*.id`, `audit_events.*`, `files.sha256` after AVAILABLE |
| No cascade deletes | FKs are `ON DELETE RESTRICT` except tokens/sessions → users (`CASCADE` on hard purge only) |
| Uniqueness | Always include `organization_id` unless the value is globally unique by design (hostnames, session token hashes, permission codes) |
| Check constraints | Dates ordered, percentages 0–100, status sets, scope consistency on `role_assignments` |
| Settings | Typed registry in code; DB stores JSONB; reads cached per tenant with version; writes audited |
| Naming | `snake_case`; constraints named `<table>_<cols>_<kind>` (pk, uq, fk, ck, ix, ex) for deterministic migrations |
| Seeds | System roles, permissions, default settings, period types seeded per tenant by the provisioning routine (idempotent) |

## 6. Partitioning, indexing and growth

| Table | Strategy |
|---|---|
| `audit_events` | Range partition monthly on `occurred_at`; local indexes; older partitions detached to cold storage after 12 months; automated partition creation 3 months ahead |
| `attendance_records` (M4) | Not partitioned initially; indexes `(student_id, session_date)`, `(course_offering_id, student_id)`; revisit at ~50M rows (partition by `session_date` year) |
| `notifications` | Time-based purge (180 d); index `(recipient_user_id, read_at, created_at desc)` |
| `outbox_events` | Partial index on unprocessed; processed rows purged after 14 days |
| `sessions`, tokens | Purge expired nightly |
| Search | `pg_trgm` GIN on `users.display_name`, `students.admission_number`; created in the migration that adds the table |
| All FKs | Indexed; checked by schema linter |

## 7. Migration policy

- Versioned SQL migrations (Drizzle Kit generates; humans review; helpers for RLS/immutability triggers/exclusion constraints are hand-written SQL).
- Forward-only in production; each migration has a tested down path in CI for the last N migrations (data-destructive ones excepted and flagged).
- **Expand → migrate → contract** for any change touching a populated column.
- Migrations run as `app_migrator` in the deploy pipeline *before* new app version starts; app refuses to boot if schema version < required.
- CI creates a fresh DB, applies all migrations, runs the schema linter (S-2) and the RLS tests (S-4) against it.
- Seeds are separate from migrations and idempotent.

---

## 8. Backup, restore and retention (design)

- Daily full + continuous WAL archiving (cloud-managed PITR where available); RPO ≤ 15 min, RTO ≤ 4 h (pilot target; proven by a restore drill before go-live).
- Object storage versioning on `sensitive` and `generated` buckets; lifecycle rules match `retention_policies`.
- Backups encrypted; keys separate from data; backup access audited.
- Purged/erased data persists in backups until rotation (documented, ≤35 days).

## 9. Verification harness (what the database layer must prove in CI)

| Check | How |
|---|---|
| Every table in `app` has `organization_id`, ENABLE+FORCE RLS, `tenant_isolation` policy | Linter over `pg_class`, `pg_policy` |
| Student-bearing tables have the restrictive policy | Linter over a declared list (`student_scoped_tables`) |
| Append-only tables reject UPDATE/DELETE as `app_runtime` | Behavioral test |
| Unset tenant → 0 rows on every table | Loop over all tables |
| Cross-tenant insert/update blocked by `WITH CHECK` | Loop over tables with generated fixtures |
| FK columns indexed | Linter |
| Enum CHECKs equal code constants | Test |
| Exclusion constraints reject overlaps | Targeted tests (role assignments dup, later: memberships, primary faculty) |
| `app_runtime` cannot `ALTER`, `CREATE`, `SET ROLE` | Behavioral test |

**Day-1 spike (Milestone 1 gate):** before building modules, prove on a throw-away branch: UUIDv7 insert performance, `withTenant` + PgBouncer transaction pooling, RLS + FORCE with a non-owner role, partitioned `audit_events` with RLS, and an exclusion constraint with `btree_gist`. Failures here change this document before any feature work.
